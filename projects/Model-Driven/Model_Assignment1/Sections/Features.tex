\section{Features}

The current high-level features of \textbf{FridgeIO} include:

\begin{itemize}
    \item \textbf{User Management:} registration, login, account management (including password changes and account deletion).
    \item \textbf{Inventory Management:} add, edit, and delete food items, mark favorites, and track expiration dates.
    \item \textbf{Inventory Overview:} overview page showing current stock, favorite items, and items nearing expiration.
    \item \textbf{Recipe Management:} create, edit, and manage recipes that are linked to items in the fridge.
    \item \textbf{API:} web-based frontend connected to a backend through a REST API (supporting GET, POST, PUT, DELETE).
    \item \textbf{Database:} cloud-hosted(launched beside the API) NoSQL database for storing user data, inventory, and recipes.
    \item \textbf{Security:} password hashing and salting to protect user credentials.
\end{itemize}

\subsection{Potential Additional Features}

Some features that could be added to FridgeIO is:

\begin{itemize}
    \item \textbf{Public Food API Integration:} Public food API so we don't need to manually add each food.
    \item \textbf{Camera Usage:} support for barcode scanning and AI-based food recognition.
    \item \textbf{Mobile Application:} In addition or instead of a web application (Had not learned how to make mobile apps before this project)
    \item \textbf{Social Features:} recipe sharing and recommendations between users.
    \item \textbf{Household Fridge:} shared inventory management across multiple users in the same household.
    \item \textbf{Statistics and Analytics:} dashboards showing consumption patterns and food waste.
    \item \textbf{Automatic Recipe Suggestions:} AI-powered or arrhythmic based meal recommendations based on available ingredients.
\end{itemize}
